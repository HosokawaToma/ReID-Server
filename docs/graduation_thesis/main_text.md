# 2 システムの概要

## 2.1 全体像

本研究では，大学建物内における人の移動を，カメラ画像情報に基づいて継続的に把握することを目的として，人流解析システムを構築した．
システム全体の処理は，「カメラ画像の収集」「人物の検出」「人物画像の品質チェック」「人物の再同定（ReID）」「移動情報としての集計・検索」という流れで構成される．

## 2.2 サーバ構成

本システムは，外部からの画像投入と分析結果の参照を受け付ける WebAPI サーバを中心に構成される．
一方で，カメラ画像から人物の検出，品質チェック，再同定を行う処理は，計算負荷が高いため，WebAPI のリクエスト処理とは別プロセスに分離し，非同期に実行される．
この分離により，API 応答を安定させやすくなり，また別プロセスを複数起動することで，計算資源が許す範囲で並列実行数を増やすことができる．

人物の再同定（ReID）では，人物画像から抽出される特徴量ベクトルと，それに紐付くメタ情報（観測時刻，カメラ ID，割当人物 ID 等）を継続的に保存する必要がある．
そのため，DB にはベクトル型データを保持できることが求められる．
また，収集されるデータは多くなることが見込まれるため，類似検索が可能なシステムが望ましい．
本システムでは，PostgreSQL と拡張機能 pgvector を用いて特徴量ベクトルを保存し，類似検索には pgvector が提供する距離関数とインデックス機構（近似最近傍探索を含む）を利用する．

## 2.3 カメラ画像の収集

各カメラ端末から取得した画像，カメラ ID，および撮影時刻を WebAPI を利用しサーバへ集約する．
人流解析では「どの人物が，いつ，どこで観測されたか」が主要な情報となるため，撮影時刻の取り扱いは特に重要である．
具体的には，端末ごとに時刻がずれていると，人物の観測順序が入れ替わったり，移動時間が不自然になったりするため，端末側での時刻同期（例として NTP による同期）を前提とし，サーバでは受信時刻ではなく撮影時刻を基本として処理する．

収集段階で保存される画像は，検出モデルが人物領域を十分に含む解像度を維持する必要がある．
また，ReIDモデルが適切な特徴量を抽出できるよう，画像の色味が失われてしまうことを避ける必要がある．
本研究では，この後段の検出・品質チェック・ReID の入出力を前提に，収集する画像を人物検出が成立する画質で継続的に投入する．

### 2.3.2 人物の検出

人物の再同定には，人物が一人だけ写った人物画像が必要となる．
そのため，カメラの全域画像から人物領域のみを推定する必要がある．
本研究では，物体検出モデルである YOLO（You Only Look Once）を利用し，人物クラスのバウンディングボックスを推定することで人物領域を切り出す．

物体検出の出力は一般に，複数の候補バウンディングボックスと各候補の信頼度（confidence）である．
同一人物に対して複数候補が重複して出力される場合があるため，非極大抑制（Non-Maximum Suppression，NMS）等により重複候補を統合し，最終的な人物領域を決定する．
このとき信頼度閾値を高くすると誤検出は減るが見逃しが増え，低くすると見逃しは減るが誤検出が増えるため，後段の品質チェックと組み合わせた全体最適として閾値を設計する必要がある．

検出によって得られた人物領域は，ReID 用の入力画像として切り出される．
切り出しの際にバウンディングボックスを厳密に人物輪郭へ合わせすぎると，姿勢変化や検出誤差によって身体の一部が欠けやすい．一方で余白を取りすぎると背景が多く混入し，照明や背景の違いに敏感になって特徴量の安定性が低下する可能性がある．
そのため，後段の姿勢推定や特徴抽出の特性を踏まえた適切な余白設定が必要となる．

### 2.3.3 人物画像の品質チェック

人物の再同定に用いる人物画像は，「一人だけが全身が写った鮮明な画像」のみにしなければ精度が大幅に落ちてしまう．
例えば，体の一部が隠れた画像を使用してしまうと，体の一部が隠れたという特徴を含んでしまい，同じ人物であるのにも関わらず特徴量の一致率が低下してしまい，精度が落ちてしまう．
他には，二人以上が写った画像を使用してしまうと，二人の特徴が含まれてしまい，一つの人物 ID を二人が共有してしまい，結果的に全体の精度が落ちてしまう．
実際，有名なデータセットである Market1501 では，全身が写っていない人物画像や複数人が写っている人物画像は「ジャンクデータ」と設定しており，評価時にはこれを省く必要がある．
ジャンクデータを省かず評価を行ってしまうと，結果が悪くなってしまう．
Market1501 などのデータセットでは，事前にジャンクデータかどうかラベリングされているが，実環境ではラベリングを行う必要がある．
本研究では，「全身が写っていない人物画像」と「複数人が写っている人物画像」を「ジャンクデータ」と判定する．
これには，人物検出および姿勢推定を用いることで，自動的に判定を行うことができる．

まず，人物検出の結果として得られる人物バウンディングボックスの数を用いて，画像内の人物数を推定し，単独の人物が写る画像のみを選別する．
ここで，検出数が 0 の場合は人物が写っていないため除外し，2 以上の場合は複数人物が混在している可能性が高いため除外する．
ただし，鏡や掲示物の人物写真などが誤検出される場合もあるため，信頼度閾値や領域サイズの下限（極端に小さい検出の除外）を併用し，誤検出の影響を抑える．

次に，姿勢推定モデル（例として YOLO 系の pose 推定モデル）を用いて，関節点（キーポイント）を推定し，全身が写っている画像のみを選別する．
全身が写っているかの判定は，頭部，肩，肘，手首，腰，膝，足首等の主要キーポイントが一定以上の信頼度で観測されるか，および人物バウンディングボックスが画像端で切れていないか等の条件で定義できる．
例えば，足首キーポイントが高信頼度で検出されない場合，足元が画角外にある可能性が高く，全身画像としては不適である．

本研究の品質チェックでは，少なくとも「単独人物であること」と「全身が写っていること」を必須条件として扱い，ReID 入力の品質を担保する．

### 2.3.4 人物の再同定

人物再同定には CLIP-ReID を用いる．
ReID は，人物領域画像を入力として固定長の特徴量ベクトル $\mathbf{f} \in \mathbb{R}^{d}$ を抽出し，過去に登録済みの特徴量集合との類似度に基づき，同一人物である可能性が最も高い候補を選択する問題として定式化できる．
本システムでは，各人物領域画像から特徴量を抽出し，蓄積済みの特徴量との照合を行うことで人物 ID を割り当てる．

CLIP-ReID は，画像とテキストの対照学習で事前学習された CLIP（Contrastive Language-Image Pre-training）系表現を ReID に適用し，人物画像の識別に有用な埋め込み空間を構成する手法である．
一般に，従来の ReID は分類損失やトリプレット損失等により「同一人物は近く，別人物は遠い」特徴空間を学習する．
CLIP 系表現を導入する狙いは，事前学習によって獲得された頑健な視覚表現を利用し，照明条件，背景，視点（カメラ角度）や服装のしわ等の変動に対して，識別に有用な情報を抽出しやすくする点にある．

照合（同一性判定）には，特徴量間の距離尺度としてコサイン類似度を用いる．
特徴量を $\ell*{2}$ 正規化したうえで，2 つの特徴量 $\mathbf{f}*{a}, \mathbf{f}_{b}$ の類似度を

$\mathrm{sim}(\mathbf{f}_{a}, \mathbf{f}_{b})=\frac{\mathbf{f}_{a}^{\top}\mathbf{f}_{b}}{\|\mathbf{f}_{a}\|\|\mathbf{f}\_{b}\|}$

と定義すると，値が 1 に近いほど類似している．
対象画像の特徴量と，蓄積済み特徴量との類似度を計算し，最大類似度を与える登録特徴量の人物 ID を候補として取得する．

人物 ID の割当はオープンセット識別（登録されていない人物が現れる）であるため，最大類似度が閾値を上回る場合に既存人物へ同定し，閾値に満たない場合に新規人物として新たな人物 ID を発行する．
閾値は，別人同士の類似度分布と同一人物同士の類似度分布の重なりに依存して最適値が変化するため，実環境データに基づく調整が必要である．

最終的に，割当人物 ID と，観測時刻，カメラ ID，特徴量ベクトルを DB に保存する．

### 2.3.5 移動情報としての集計・検索

ReID の結果として得られるのは，「人物 ID」「観測時刻」「カメラ ID」という離散的な観測点列である．
人流解析としては，これらを集約し，「特定時間帯における地点ごとの滞在人数」「地点間の遷移回数」「滞在時間分布」などの移動統計へ変換する必要がある．

集計の基本は，人物 ID ごとに観測点列を時刻順に並べ，同一人物の連続観測を一つの軌跡として扱うことである．
例えば，人物 ID がカメラ A で観測された後にカメラ B で観測されれば，A から B への遷移が 1 回生じたとみなせる．
このとき，カメラの設置位置関係（階や区画）を前提として，到達不可能な遷移（物理的に移動できない時間での遷移）を除外するルールを導入すると，誤同定の影響を受けにくい集計が可能となる．

検索では，指定期間や指定地点（カメラ）を条件として，観測点列や遷移統計を取り出すことを想定する．
これにより，例えば「ある時間帯に特定地点を通過した人数」や「混雑が発生しやすい遷移経路」などを，画像そのものではなく集約情報として参照できる．
