# 1 序論

## 1.1 大学で人の移動を把握する必要性

大学建物内における人の移動を把握することは，利用者がどの地点で滞在し，どの経路で移動しているかという行動の実態を，観測に基づいて記述することに相当する．この情報は，利用者が経験する混雑，待ち時間，回遊のしやすさといった体験の質を規定する要因である．さらに，時間帯ごとの混雑の偏りや，特定地点への集中といった現象を観測により把握できれば，掲示や誘導の改善，設備運用の調整といった具体的な改善策へ接続できる（［1］）．

また，人の移動は建物の空間構成と密接に関係するため，通路や出入口の配置，滞在を生む空間の設計が想定どおりに機能しているかを，観測結果に基づいて検討できる．すなわち，人流の観測は，建築計画における動線の評価や，空間利用の偏りの検出に利用でき，設計と運用の両面で改善点を抽出する基盤となる（［2］）．

## 1.2 人流の解析方法のレビュー

### 1.2.1 マクロ（都市間レベル），街区や建物内レベル，部屋内のレベルに分ける

人流の解析は，対象とする空間スケールに応じて用いる観測手段が変化する．マクロレベルでは，GPS や携帯電話基地局等に基づく位置情報を用いて，個人の移動軌跡や滞在の分布を推定する方法が広く用いられる（［3］）．

街区や建物内レベルでは，Wi-Fi 端末が発する管理フレームに含まれる識別情報を受信し，観測点（アクセスポイントやセンサ設置位置）ごとの受信履歴を用いて移動を推定する方法がある（［4］）．

部屋内のレベルでは，カメラ画像を入力として人物を検出し，人物の位置や出現を観測する方法がある．YOLO の物体検出モデルはカメラ映像を入力することで人物領域を推定できるため，カメラの画角内に収まる人物の出現と位置を観測できる（［5］）．

### 1.2.2 街区や建物内レベルの従来手法の問題点と解決案

携帯電話の位置情報を使った手法は，ユーザが電話をかけた時の基地局の位置情報を取得することで，大まかなユーザの位置を把握することができる．この方法は電話を利用する全てのユーザからデータを収集することができるため，大規模な人流の把握が可能である．しかし，そもそもユーザが電話をかけなければ位置情報が取得できず，さらに取得できる情報の粒度がユーザの通話頻度に依存してしまうため，安定した移動の把握が困難である（［6］）．

GPS を使用した位置情報の取得は，GPS から位置情報を取得し発信する端末をユーザが所持することで，ユーザの位置を把握することができる．この方法は，GPS から得られる位置情報を利用するため，携帯電話に比べ細かい粒度で詳細な位置情報を取得することができる．しかし，端末が GPS を利用して位置情報を取得するための機能を搭載しており，その機能をユーザが有効にしている必要がある．この条件を満たさないユーザには傾向があるため，収集できるデータにユーザ属性に依存したバイアスが生じ得る（［7］）．さらに，屋内では衛星信号の受信状況が不安定になりやすく，建物内の位置推定を主目的とする場合には適用が難しい（［7］）．

Wi-Fi に基づく方法は，端末識別子として MAC アドレスを利用するが，近年の端末はプライバシ保護のために MAC アドレスのランダム化を行い，観測点間で同一端末として追跡することを困難にしている（［8］）．このため，MAC アドレスに依存する追跡は長期的な安定性を欠き，継続運用の前提として脆弱である．

以上の制約を踏まえると，建物内の地点と時刻に結び付いた観測を得るには，カメラ画像に基づいて人物の出現を直接観測する方法が有力となる．画像に基づく方法は，観測対象を端末所持に依存させず，人そのものを入力として扱えるため，屋内での細粒度な移動の把握に適する（［15］）．ただし，建物内で複数台のカメラを用いる場合には，地点ごとの観測を同一人物として結び付ける必要があり，この対応付けが成立しなければ移動として集計できない（［9］）．

### 1.2.3 ReID 技術のレビュー

カメラに基づいて移動を把握する際には，同一人物が異なる地点のカメラに写った観測を結び付ける必要がある．人物再同定（Person Re-Identification，ReID）は，異なるカメラ，異なる時刻で撮影された人物画像の間で同一人物性を推定する課題であり，監視カメラネットワーク等を背景として研究が発展してきた（［9］）．

ReID では，照明，背景，視点，遮蔽，姿勢変化といった撮影条件の差により，同一人物の見えが大きく変化することが根本的な難しさとなる．この難しさに対して，人物画像から特徴量を抽出し，特徴量空間上で同一人物を近く，別人物を遠くに配置するよう学習する深層学習ベースの手法が主流となり，識別性能は大きく向上してきた（［10］）．

近年は，大規模事前学習により獲得された表現を下流課題へ転用する潮流が強まり，Transformer に基づく視覚表現の導入が進んでいる（［11］）．さらに，画像とテキストの対照学習により学習された CLIP のような表現は，視覚特徴の頑健性と汎化性を持つことが報告されている（［12］）．この種の事前学習表現を ReID に適用する試みとして CLIP-ReID が提案されている（［13］）．

## 1.3 この研究の目的

### 1.3.1 CLIP-ReID を使って大学の建物の内の人流を解析することが可能かどうかを検討する

本研究の第一の目的は，大学建物内に設置した定点カメラから得られる画像に基づいて，人物検出と ReID を組み合わせることで，個人の移動を継続的に把握し，人流として集計可能かどうかを検討することである．すなわち，地点ごとの「人物の出現」を検出し，それらを同一人物として対応付けることで，観測点列を軌跡として再構成できるかを確認する．このとき，ReID には CLIP 系表現を利用する CLIP-ReID を用い，屋内環境における撮影条件の変動に対しても，外観特徴に基づく同一人物性推定が成立するかを確認する（［13］）．

### 1.3.2 将来的に拡張可能で大学内でこれからも使い続けられるようなシステムを構築する

本研究の第二の目的は，運用の継続を前提として，カメラの追加や ReID モデルの変更といった構成要素の入れ替えが可能な人流解析システムを構築することである．すなわち，観測入力（カメラ）と推論モデル（検出，品質チェック，ReID）が変化しても，収集から照合，蓄積，集計までの処理が破綻せず，性能と計算資源の制約に応じて拡張できる設計を検討する（［14］）．

# 2 システムの概要

## 2.1 全体像

本研究では，大学建物内における人の移動を，定点カメラから得られる画像に基づいて継続的に把握することを目的として，人流解析システムを構築した．本システムが扱う観測は，時刻と観測地点（カメラ設置位置）に紐付いた画像から人物を検出し，人物外観を表す特徴量へ変換し，特徴量同士の類似度に基づいて同一人物性を推定する過程として整理できる．

システム全体の処理は，カメラ画像の収集，人物の検出，人物画像の品質チェック，人物の再同定（ReID），移動情報としての集計・検索から構成される．ここで重要な点は，個々の処理が独立したモジュールとして直列に並ぶだけではなく，後段の推定精度と運用上の安定性が，前段の入力品質や計算資源の制約に強く依存する点にある．例えば，人物検出の誤検出や見逃しは品質チェックの判定分布を変化させ，品質チェックを通過した画像の偏りは ReID の特徴量分布と閾値設計を変化させる．さらに，ReID の誤差は集計結果に伝播し，移動統計において到達不可能な遷移や軌跡の断片化として現れる．したがって，本システムは，検出から集計までを一貫したパイプラインとして設計し，誤差の伝播経路を前提に，段階的に誤差要因を抑制する設計とした．

また，本研究の狙いは，単発の解析ではなく，大学建物内の人流を継続的に観測し，必要な期間や地点に対して後から検索できる運用形態を実現する点にある．そのため，処理は入力到着のたびに逐次実行されるオンライン処理として構成し，観測結果は時刻と地点のメタ情報とともに蓄積する．この蓄積情報は，後段で混雑度や遷移回数などの統計量へ変換されるため，観測の粒度，時刻の整合性，人物 ID 付与の一貫性が，最終出力の解釈可能性を規定する．

## 2.2 サーバ構成

本システムは，外部からの画像投入と分析結果の参照を受け付ける WebAPI サーバを中心に構成される．ただし，カメラ画像から人物の検出，品質チェック，再同定を行う処理は計算負荷が高く，また GPU 資源の有無や同時実行数に応じて処理時間が変動しやすい．このため，WebAPI のリクエスト処理と推論処理を同一実行系に同居させると，入力の増加が即座に API 応答遅延へ波及し，システム全体の可用性を低下させる．そこで，本システムでは，WebAPI と推論処理を別プロセスへ分離し，推論処理は非同期に実行される構成とした．この分離により，API は入力受付と結果参照という I/O 主体の役割に集中し，推論処理は計算資源が許す範囲で並列度を調整できる．

人物の再同定では，現在の入力特徴量を過去の特徴量集合と照合することが必要である．したがって，人物画像から抽出される特徴量ベクトルと，それに紐付くメタ情報（観測時刻，カメラ ID，割当人物 ID 等）は永続化し，検索可能な形で保持する必要がある．ここで，特徴量の次元を $d$，蓄積件数を $N$ とすると，全探索により類似度を計算する場合の計算量は $O(Nd)$ となり，$N$ の増加に伴って照合遅延が線形に増大する．この遅延は，オンライン処理としての連続観測に対して致命的となるため，厳密最近傍ではなく近似最近傍探索を許容しつつ，高速に近傍候補を得る仕組みが必要となる．

以上より，データの永続化に用いる DB には，(i) ベクトル型データを保持できること，(ii) ベクトル間距離に基づく検索を実行できること，(iii) 近似最近傍探索に対応したインデックス機構を備えること，が要求される．本システムでは，PostgreSQL と拡張機能 pgvector を用いて特徴量ベクトルを保存し，類似検索には pgvector が提供する距離関数とインデックス機構（近似最近傍探索を含む）を利用する．この構成により，照合処理のボトルネックを DB 側のベクトル検索に集約し，推論プロセス側は「特徴量の生成」と「検索結果に基づく人物 ID の決定」という役割分担が可能となる．

## 2.3 画像処理パイプライン（収集から ReID，集計まで）

### 2.3.1 カメラ画像の収集

各カメラ端末から取得した画像は，観測地点を識別するカメラ ID と撮影時刻を付与したうえで，WebAPI を介してサーバへ集約する．ここで入力画像は，人物領域の切り出しをサーバ側で実施する前提であり，端末側ではカメラ全体画像をそのまま送信する．この設計は，端末側の計算資源や実装の差異を最小化し，検出モデルの更新や品質チェック条件の変更をサーバ側に集約できる利点を持つ．一方で，全体画像は人物領域に比べて情報量が大きく，ネットワーク帯域や保存容量に負担を与え得るため，送信周期と画像サイズの設計が運用上の制約となる．

収集段階で保存される画像は，人物検出モデルと ReID モデルが十分に性能を発揮できる画質である必要がある．特に ReID は外観の微細な差異を利用するため，強い圧縮や色再現の破綻は特徴量の安定性を低下させ，同一人物であっても特徴量が大きく変動する原因となる．したがって，収集画像に対しては，人物の輪郭と衣服のテクスチャが識別可能であり，かつ色味が極端に失われないことを要件として設定した．

カメラ画像収集の入力仕様は，最低限，画像本体，カメラ ID，撮影時刻の三点から構成される．カメラ ID は観測地点を表す識別子であり，設置位置（階，通路，部屋など）と一対一に対応付くことが望ましい．撮影時刻は端末側で付与された時刻であり，複数カメラ間での時系列整合性を担保するため，時刻同期が成立していることを前提とする．この時刻情報は，後段の集計において観測点列を時刻順に並べる基準となるため，誤差が大きい場合は到達不可能遷移の判定や滞在時間推定に直接的な歪みを与える．

収集画像は後段の人物検出および ReID の性能を直接左右する．典型的な劣化要因として，低照度によるノイズ増加，強い逆光や白飛び，低解像度による人物領域の情報欠落，動体ブレ，画像圧縮によるブロックノイズが挙げられる．本研究の目的はシステムとしての人流解析可能性の検討であるため，まずは人物検出が成立し，かつ外観特徴が抽出可能な品質の入力を継続的に収集することを前提とした．

### 2.3.2 人物の検出

人物の再同定には，人物が一人だけ写った人物画像が必要となる．
そのため，カメラの全域画像から人物領域のみを推定する必要がある．
本研究では，物体検出モデルである YOLO（You Only Look Once）を利用し，人物クラスのバウンディングボックスを推定することで人物領域を切り出す．

YOLO は一段の推論で位置推定とクラス推定を同時に出力する one-stage 検出器として整理でき，画像全体に対して多数の候補領域を生成し，各候補に対してクラスと信頼度を推定する．本研究においては，人流解析の入力として人物領域を得ることが目的であるため，多クラス分類の出力のうち人物クラスに対応する候補のみを利用する．検出の見逃しは後段の ReID 入力欠損につながり，誤検出は品質チェックを通過した場合に誤った人物 ID の生成につながるため，信頼度閾値と後段の品質チェックを組み合わせた全体設計が必要となる．

物体検出の出力は一般に，複数の候補バウンディングボックスと各候補の信頼度（confidence）である．
同一人物に対して複数候補が重複して出力される場合があるため，非極大抑制（Non-Maximum Suppression，NMS）等により重複候補を統合し，最終的な人物領域を決定する．
このとき信頼度閾値を高くすると誤検出は減るが見逃しが増え，低くすると見逃しは減るが誤検出が増えるため，後段の品質チェックと組み合わせた全体最適として閾値を設計する必要がある．

NMS は，候補同士の重なり度合いを IoU（Intersection over Union）で評価し，高信頼度の候補を残しつつ重複候補を抑制する処理である．
IoU を

$\mathrm{IoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}$

と定義すると，IoU が大きいほど同一領域を指している可能性が高い．
NMS の IoU 閾値を低くすると重複除去が強くなり，同一人物の多重検出は減るが，近接した別人物（混雑環境）を誤って 1 人に統合するリスクが増える．
逆に IoU 閾値を高くすると近接人物の分離は保ちやすいが，多重検出が残りやすい．
本研究では，後段で「単独人物であること」を必須条件として品質チェックを行うため，混雑環境での多重検出や誤統合がそのまま ReID 入力に流れ込まないよう，品質チェックと合わせて閾値を調整する設計とした．

検出によって得られた人物領域は，ReID 用の入力画像として切り出される．
切り出しの際にバウンディングボックスを厳密に人物輪郭へ合わせすぎると，姿勢変化や検出誤差によって身体の一部が欠けやすい．一方で余白を取りすぎると背景が多く混入し，照明や背景の違いに敏感になって特徴量の安定性が低下する可能性がある．
そのため，後段の姿勢推定や特徴抽出の特性を踏まえた適切な余白設定が必要となる．

人物領域の切り出しは，ReID の特徴量抽出における情報の取捨選択に相当する．
一般に ReID は人物外観に依存するため，背景の混入は「背景が似ているから同一人物に見える」という誤同定（偽陽性）を誘発し得る．
他方で，人物領域が欠けると，衣服のパターンや持ち物など識別に有用な情報が失われ，見逃し（偽陰性）を誘発し得る．
したがって，切り出し余白は「人物情報の欠落」と「背景混入」を同時に抑えるように設計すべきであり，後段の品質チェック（全身が写っているか）と整合する余白設定が重要となる．

### 2.3.3 人物画像の品質チェック

人物の再同定に用いる人物画像は，単独人物であり，全身が写っており，かつ外観特徴が抽出可能な鮮明さを満たす必要がある．この条件を満たさない画像を ReID へ投入すると，特徴量が本来の外観差異ではなく，遮蔽，切れ，混在，ブレといった撮影条件由来の要因に支配され，同一人物であっても特徴量が近接しにくくなる．結果として，照合の最大類似度が低下し，既存人物の分割や誤同定の増加を招く．

また，複数人物が同一画像内に混在する場合，切り出しが不適切であると，背景や他者の衣服が人物領域に混入し得る．この混入は，人物 ID を本来共有すべきでない別人物間で類似度を上げる方向に作用し，誤同定を誘発しやすい．そのため，ReID 入力の品質を担保するためには，入力段階で不適切な画像を排除する品質チェックが不可欠となる．

実際，有名なデータセットである Market1501 では，全身が写っていない人物画像や複数人が写っている人物画像はジャンクデータとして扱われ，評価時には検索対象から除外する必要がある．データセットではジャンクデータが事前にラベリングされる一方，実環境では入力が逐次到着し，手動ラベリングを前提とできないため，自動的な品質判定が必要となる．本研究では，全身が写っていない人物画像と，複数人が写っている人物画像をジャンクデータとして判定し，人物検出および姿勢推定により自動判定する．

まず，人物検出の結果として得られる人物バウンディングボックスの数を用いて，画像内の人物数を推定し，単独の人物が写る画像のみを選別する．
ここで，検出数が 0 の場合は人物が写っていないため除外し，2 以上の場合は複数人物が混在している可能性が高いため除外する．
ただし，鏡や掲示物の人物写真などが誤検出される場合もあるため，信頼度閾値や領域サイズの下限（極端に小さい検出の除外）を併用し，誤検出の影響を抑える．

次に，姿勢推定モデル（例として YOLO 系の pose 推定モデル）を用いて，関節点（キーポイント）を推定し，全身が写っている画像のみを選別する．
全身が写っているかの判定は，頭部，肩，肘，手首，腰，膝，足首等の主要キーポイントが一定以上の信頼度で観測されるか，および人物バウンディングボックスが画像端で切れていないか等の条件で定義できる．
例えば，足首キーポイントが高信頼度で検出されない場合，足元が画角外にある可能性が高く，全身画像としては不適である．

本研究の品質チェックでは，「単独人物であること」と「全身が写っていること」を必須条件として扱い，ReID 入力の品質を担保する．

### 2.3.4 人物の再同定

人物再同定には CLIP-ReID を用いる．
ReID は，人物領域画像を入力として固定長の特徴量ベクトル $\mathbf{f} \in \mathbb{R}^{d}$ を抽出し，過去に登録済みの特徴量集合との類似度に基づき，同一人物である可能性が最も高い候補を選択する問題として定式化できる．
本システムでは，各人物領域画像から特徴量を抽出し，蓄積済みの特徴量との照合を行うことで人物 ID を割り当てる．

CLIP-ReID は，画像とテキストの対照学習で事前学習された CLIP（Contrastive Language-Image Pre-training）系表現を ReID に適用し，人物画像の識別に有用な埋め込み空間を構成する手法である．
一般に，従来の ReID は分類損失やトリプレット損失等により「同一人物は近く，別人物は遠い」特徴空間を学習する．
CLIP 系表現を導入する狙いは，事前学習によって獲得された頑健な視覚表現を利用し，照明条件，背景，視点（カメラ角度）や服装のしわ等の変動に対して，識別に有用な情報を抽出しやすくする点にある．

ReID の入力は人物画像であり，出力は特徴量（埋め込み）である．本研究では，特徴量を「同一人物性を表す指標」として利用し，照合によって人物 ID を割り当てる．
ここで，ReID の本質は「クラス数が事前に固定されない識別」である．すなわち，運用中に初めて現れる人物（未登録人物）を扱う必要があるため，単純な分類問題ではなく，距離空間上での近傍判定として扱うことが自然である．

距離空間上の近傍判定として ReID を扱う場合，照合は検索問題として理解できる．すなわち，クエリ特徴量 $\mathbf{f}_{q}$ に対して，DB に格納された特徴量集合 $\mathbf{f}_{i}$ から類似度最大の候補を取り出し，その候補が十分に近い場合のみ同一人物と判定する．このとき，十分に近いかどうかを決める閾値は，人物 ID 付与の安定性と誤同定率を支配するため，集計結果の信頼性に直結する．本研究では，人流解析の目的に照らして誤同定の抑制を優先し，閾値未満の観測は新規人物として分割する方針を採用する．

また，本研究の運用条件として，人物外観は日を跨いで大きく変化し得る（服装の変更）．
画像の RGB 値に基づく特徴抽出では，衣服色やテクスチャの影響が強いため，別日データまで同一人物として結び付けると誤同定が増える可能性が高い．
したがって，本研究では，人流解析に用いる候補画像（照合対象）を原則として同日内に限定し，外観変動（特に服装変化）による特徴量分布のずれを抑制する設計とした．

照合（同一性判定）には，特徴量間の距離尺度としてコサイン類似度を用いる．
特徴量を $\ell_{2}$ 正規化したうえで，2 つの特徴量 $\mathbf{f}_{a}, \mathbf{f}_{b}$ の類似度を

$\mathrm{sim}(\mathbf{f}_{a}, \mathbf{f}_{b})=\frac{\mathbf{f}_{a}^{\top}\mathbf{f}_{b}}{\|\mathbf{f}_{a}\|\|\mathbf{f}_{b}\|}$

と定義すると，値が 1 に近いほど類似している．
対象画像の特徴量と，蓄積済み特徴量との類似度を計算し，最大類似度を与える登録特徴量の人物 ID を候補として取得する．

コサイン類似度を用いる理由は，特徴量の大きさ（ノルム）ではなく方向に基づいて類似性を測ることで，照明変動等に起因するスケール差の影響を受けにくくするためである．
特に $\ell_{2}$ 正規化後は $\|\mathbf{f}\|=1$ となり，

$\mathrm{sim}(\mathbf{f}_{a},\mathbf{f}_{b})=\mathbf{f}_{a}^{\top}\mathbf{f}_{b}$

と内積そのものに一致する．したがって，類似度計算は高速であり，DB 上でも距離関数として扱いやすい．

人物 ID の割当はオープンセット識別（登録されていない人物が現れる）であるため，最大類似度が閾値を上回る場合に既存人物へ同定し，閾値に満たない場合に新規人物として新たな人物 ID を発行する．
閾値は，別人同士の類似度分布と同一人物同士の類似度分布の重なりに依存して最適値が変化するため，実環境データに基づく調整が必要である．

この閾値判定は，誤同定（別人を同一と判定）と分割（同一人物を別人として新規発行）のトレードオフを支配する．
誤同定が増えると，人流解析では「存在しない遷移」が増え，遷移回数や混雑推定が大きく歪む．
一方で分割が増えると，同一人物の軌跡が断片化し，滞在時間が短く見積もられ，遷移が過小評価される可能性がある．
したがって，人流解析の目的に照らすと，一般に誤同定の抑制を優先し，分割をある程度許容する設計が妥当となる．本研究でもこの方針に基づいて閾値を設計する．

最終的に，割当人物 ID と，観測時刻，カメラ ID，特徴量ベクトルを DB に保存する．

### 2.3.5 移動情報としての集計・検索

ReID の結果として得られるのは，「人物 ID」「観測時刻」「カメラ ID」という離散的な観測点列である．
人流解析としては，これらを集約し，「特定時間帯における地点ごとの滞在人数」「地点間の遷移回数」「滞在時間分布」などの移動統計へ変換する必要がある．

集計の基本は，人物 ID ごとに観測点列を時刻順に並べ，同一人物の連続観測を一つの軌跡として扱うことである．
例えば，人物 ID がカメラ A で観測された後にカメラ B で観測されれば，A から B への遷移が 1 回生じたとみなせる．
このとき，カメラの設置位置関係（階や区画）を前提として，到達不可能な遷移（物理的に移動できない時間での遷移）を除外するルールを導入すると，誤同定の影響を受けにくい集計が可能となる．

集計における重要点は，「観測点列」から「移動」の概念を導入する際に，時間窓と連続性を定義することである．
例えば，同一人物が同一カメラで短時間に複数回観測される場合，それらを全て独立観測として数えると滞在人数推定が過大になる．
そのため，ある時間分解能（例として 1 分や 5 分）で観測を集約する，あるいは同一カメラでの連続観測を 1 滞在としてまとめる，といったルールが必要となる．
これらのルールは，人流解析の出力（混雑度や滞在時間）を規定するため，分析目的に応じて定義すべきである．

また，ReID の誤差は集計に伝播する．特に，誤同定は「瞬間移動」のような不自然な遷移として現れやすい．
そこで，本研究では，到達不可能遷移の除外という整合性チェックを導入し，物理的制約と時間制約に反する遷移を統計から除外することで，誤同定の影響を軽減する．
この整合性チェックは，厳密には「誤同定の検出器」として機能し得るため，将来的には誤同定が疑われる観測を再照合する等の拡張にも接続できる．

検索では，指定期間や指定地点（カメラ）を条件として，観測点列や遷移統計を取り出すことを想定する．
これにより，例えば「ある時間帯に特定地点を通過した人数」や「混雑が発生しやすい遷移経路」などを，画像そのものではなく集約情報として参照できる．

検索機能は，集計結果の利用可能性を高めるために不可欠である．
例えば，運用上は「特定期間における混雑のピーク」や「特定地点での異常（通常と異なる人数増加）」を後から確認したい場合がある．
このとき，画像を直接探索するのではなく，人物 ID と時刻と地点の組で構成される観測点列から条件検索し，必要な統計量を再計算できることは，プライバシ保護と運用性の両面で利点がある．
