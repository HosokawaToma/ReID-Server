# 2 システムの概要

## 2.1 全体像

本研究では，大学建物内における人の移動を，画像情報に基づいて継続的に把握することを目的として，人流解析システムを構築した。
システムは「カメラ画像の収集」「人物画像の生成」「人物の再同定（ReID）」「移動情報としての集計・検索」という一連の流れを，運用可能な形で一体化することを重視して設計した。

入力は，各地点で取得される時系列カメラ画像と，撮影時刻・設置場所を表す識別子などの付随情報である。
出力は，人物ごとに付与された識別子に基づく移動の系列（いつ，どの地点からどの地点へ移動したか）であり，後段の可視化や分析に利用できる形で提供する。

## 2.2 サーバ構成

本システムは，外部からの画像投入と分析結果の参照を行うための API サーバを中心に構成される。
画像処理・特徴量計算など計算負荷の高い処理は，オンラインの要求処理（API 応答）から切り離し，バックグラウンドで逐次実行する構成とした。
これにより，入力が増加した場合でも，サービスの応答性と処理の安定性を両立しやすくなる。

また，以下の役割を持つ基盤要素を組み合わせて運用する。

- 永続化ストレージ：入力画像や中間生成物を保存し，再現性のある分析と再処理を可能にする。
- データベース：撮影時刻・地点情報・人物識別子などのメタデータを管理し，検索・集計の基盤とする。特に ReID で用いる特徴量は，類似検索（近い特徴量を高速に探す）を前提とした形で扱えることが望ましい。
- キューイング機構：処理段階を疎結合にし，負荷平準化や再試行を容易にする。

## 2.3 ReID 処理

本節では，本研究で用いる ReID 処理の流れを概説する。
ReID は，カメラが異なる場合でも「同じ人物である可能性」を特徴量の類似性により推定する技術である。
本システムでは，入力カメラ画像から人物領域を切り出し，品質の低い画像を除外したうえで，人物特徴量を抽出し，時系列情報と組み合わせて同一人物推定を行う。

### 2.3.1 人物検出

入力フレームから人物の領域を検出し，個々の人物ごとに切り出した画像（人物スナップショット）を生成する。
これにより，後続処理（品質判定や特徴量抽出）を人物単位で行えるようになり，混雑環境においても扱いやすくなる。

### 2.3.2 ジャンク画像判定

ReID の精度は入力画像の品質に強く依存する。
例えば，人物が部分的にしか写っていない場合や，複数人物が重なり合う場合は，同一人物推定が不安定になりやすい。
そこで，本システムでは解析に不適な人物スナップショットを判定して除外し，以降の処理資源を有効なデータに集中させる。

### 2.3.3 特徴量抽出

ジャンク判定を通過した人物スナップショットから，深層学習モデルにより人物を表現する特徴量ベクトルを抽出する。
特徴量は「同一人物であれば近く，別人物であれば遠い」表現になるよう学習された埋め込みであり，後段の類似検索や同一人物推定に用いる。

### 2.3.4 同一人物推定

特徴量の類似度に基づき，過去の観測と照合して同一人物である可能性を推定し，人物識別子を付与する。人流解析の目的上，時刻情報を併用して「時間的にあり得る移動」の範囲に照合対象を限定することで，誤対応の抑制を図る。
これにより，人物識別子の時系列から地点間の移動（フロー）を構成できる。

## 2.4 データ保存

本システムでは，解析の再現性と運用性を考慮し，画像データとメタデータを分離して管理する。
画像はファイルとして保存し，撮影時刻・地点情報・人物識別子・特徴量などの検索に必要な情報はデータベースで管理する。

さらに，処理を段階化しているため，各段階で生成されるデータ（人物スナップショット，品質判定結果，特徴量，同一人物推定結果）が追跡できる形で保存されることが重要である。
これにより，モデル更新やパラメータ変更があった場合でも，特定期間・特定地点のデータを対象に再処理し，結果を比較・検証できる。
