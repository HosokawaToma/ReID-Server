# 設計ルール

## レイヤードアーキテクチャ

- 本システムは、三層アーキテクチャを採用している

```
┌─────────────────────────────────────┐
│   Presentation Layer                │  ← APIエンドポイント、リクエスト/レスポンス処理
├─────────────────────────────────────┤
│   Application Layer                 │  ← ビジネスロジック、ユースケース実装
├─────────────────────────────────────┤
│   Repository Layer                  │  ← データ永続化、データベースアクセス
└─────────────────────────────────────┘
```

### 各レイヤーの責務

#### Presentation Layer（プレゼンテーション層）
- ユーザインタフェースに関する責務を持つクラスを定義する
  - Web APIはエンドポイントに関する責務を持つクラスを定義する
  - バックグラウンドプロセスはプロセスに関する責務を持つクラスを定義する
- クラスはエンドポイント・プロセス単位に作成する
- `src/presentation/` に実装する

#### Application Layer（アプリケーション層）
- ビジネスロジックに関する責務を持つクラスを定義する
- クラスはビジネスロジック単位に作成する
- `src/applications/` に実装する

#### Repository Layer（リポジトリ層）
- データの永続化に関する責務を持つクラスを定義する
- クラスはデータ単位に作成する
- `src/repositories/` に実装する

## DDD駆動設計

- 本システムは、DDDアーキテクチャを採用している

## 依存関係のルール

- 各レイヤーは、基本的に一つ下の階層に位置するクラス以外に依存してはいけません
  - Presentation層 → Application層のみ依存可能
  - Application層 → Repository層、Domainモデルのみ依存可能
  - Repository層 → Domainモデルのみ依存可能

- **ライブラリ依存**: 基本的にライブラリとは依存関係を持ってはいけません
  - 標準ライブラリ以外のライブラリを使用する場合は、処理を隠蔽するクラスを定義して利用
